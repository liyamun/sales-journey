# Sales Journey

A Power Apps **code app** for the CRM side of Sales Hub, following the Klantreis from the Miro board:

```
1 Prospect          2 Lead                                                     3 Klant
Analyseren  ─►  Koude lead ─► Contact (tel/mail/netwerk) ─► Afspraak? ─► Warme lead ─► Voorstelling ─► Akkoord? ─► Fase 0 · Luisteren ─► …
Valideren                                                    └ Nee: stop                                  └ Nee: stop
```

Plus a **Dashboard**: new klanten, contacts, response, the best contact channel, trends, and who
is waiting for a follow-up.

Built on the same pattern as the Data Hub example (`aquasecurity-titanification/src/datahub`):
React + TypeScript + Vite, `@microsoft/power-apps`, the Dataverse connector, and one data seam that
no screen bypasses. Internal names are English, everything the user sees is Dutch.

## Run it

### 0 · Prerequisites (once)

- **Node.js 22** (or 20.19+) — `node -v`
- **VS Code** with the **Power Platform Tools** extension (it brings the `pac` CLI), or
  `dotnet tool install --global Microsoft.PowerApps.CLI.Tool`
- Your environment must allow code apps: Power Platform admin center → the environment → Settings →
  Product → Features → **Power Apps code apps** on. Ask your mentor if you can't see that setting.

### 1 · Look at it on sample data (no sign-in needed)

```bash
npm install
npm run dev:demo      # http://localhost:5181
```

Everything works, nothing is saved. A reload resets it.

### 2 · Connect it to your environment

```bash
pac auth create --environment https://<your-org>.crm4.dynamics.com
pac env who                                   # check you're in the right environment
pac code init --displayname "Sales Journey"   # writes environmentId into power.config.json
```

If `pac code init` complains that `power.config.json` already exists, delete that file and run it again.

Create a **Microsoft Dataverse** connection: [make.powerapps.com](https://make.powerapps.com) → your
environment → **Connections** → **New connection** → Microsoft Dataverse. Then:

```bash
pac connection list                           # copy the id of the Dataverse connection
pac code add-data-source -a "shared_commondataserviceforapps" -c <connection-id>
```

This regenerates `src/generated/` and `.power/` for your connection (the copies in the repo come
from the example, so the project compiles before you connect).

### 3 · Develop against Dataverse

```bash
npm run dev
```

The terminal prints a **Local Play** URL. Open *that one* (not localhost), in the browser where you
are signed in to Power Apps. The connectors only work inside the Power Apps host, with your own
sign-in. The rail footer says `Gegevens: Dataverse`.

### 4 · Publish

```bash
npm run build
pac code push
```

## Where things live

```
src/
  data/
    DataSource.ts        the contract: one method per journey step. NO SCREEN TALKS TO DATAVERSE DIRECTLY.
    dataverseSource.ts   the journey on the standard Sales tables (mapping below)
    dataverse.ts         the connector transport: list, create, update, actions
    demoSource.ts        sample data for `npm run dev:demo`
    source.ts            picks the source — the only place that does
    criteria.ts          the analysis rule: genoeg geld is a must, and at least 2 of the 3 criteria
    analytics.ts         every dashboard number, as pure functions over the journey events
    journeyNotes.ts      the fixed note subjects the steps write, and how the dashboard reads them
    types.ts             the shapes the screens use, plus the Dutch labels
  screens/               Overview, Prospects, Leads, Proposals (Voorstellingen), Customers (Klanten), Dashboard
  components/            AppShell (rail), ui.tsx, charts.tsx (SVG, no library), format.ts, hooks.ts
  theme/                 tokens.css (365Titans Design System colours + fonts), app.css
  generated/             generated by `pac code add-data-source` — do not edit
```

## How the Klantreis maps onto Dataverse

Only **standard Dynamics 365 Sales tables** are used, so every record also shows in Sales Hub.

| Klantreis | Dataverse |
|---|---|
| Prospect | `account` with relation type (`customertypecode`) = Prospect |
| Analyseren | `account.numberofemployees`, `account.revenue`; "maakt producten" is judged in the app |
| Valideren | creates a `lead` linked to the account (`parentaccountid`), rating Cold |
| Niet geschikt | account deactivated |
| Koude lead | `lead` with rating (`leadqualitycode`) = Cold |
| Contact via tel / mail / netwerk | lead status reason = Contacted + a note (`annotation`) |
| Afspraak? Ja → warme lead | lead rating = Warm |
| Afspraak? Nee → stop | lead disqualified (No longer interested) |
| Voorstelling geven | `opportunity` from the lead; the lead is qualified |
| Akkoord? Ja → klant | `WinOpportunity`, account relation type = Customer |
| Akkoord? Nee → stop | `LoseOpportunity` |
| Klant · Fase 0 | `account` with relation type = Customer |

Every step writes a note, so each lead and voorstelling carries its own history.

## The prospect rule

**Genoeg geld is verplicht, en minstens 2 van de 3 criteria kloppen.** So a prospect passes with
genoeg geld + meer dan 10 werknemers, or genoeg geld + maakt producten. It is checked in the screen
and again in the data layer (`isGoodProspect` in `criteria.ts`).

## The dashboard

Every journey step writes a note with a fixed subject (`journeyNotes.ts`). The dashboard reads
those notes back as events and computes everything in `analytics.ts`:

| Block | What it counts |
|---|---|
| Tiles | New klanten, gecontacteerd, gereageerd, responsgraad, afspraken, akkoord op voorstelling, won value, doorlooptijd, each compared with the period before |
| Wat kan beter | Plain sentences, only where the numbers support them: best channel, weakest response, biggest drop in the funnel, leads waiting |
| Van gevalideerd tot klant | The leads validated in the period, and how far each got |
| Welk kanaal werkt het best? | Per channel of the FIRST contact: response, afspraak, klant. Fewer than 3 leads is not ranked |
| Trends | Contacts per week (12 weeks), new klanten per month (6 months) |
| Opvolgen | Who is waiting now: not contacted yet, no reply for a week, afspraak without voorstelling, voorstelling older than 30 days |

Rates are **cohort** rates (what became of the leads that started in the period), never activity
ratios, which mix months and can go over 100%.

**Next step worth doing:** give the contact channel its own choice column on `lead`. The notes work,
but a column is sturdier and lets Sales Hub views filter on it too.

## Things to know

- **Leads made outside this app start warm.** Dynamics gives a new lead the rating Warm by default,
  so a lead typed into Sales Hub shows up under *Warme leads*.
- **The revenue threshold is a guess.** "Heeft genoeg geld" means annual revenue of at least
  €1,000,000 (`MIN_REVENUE_EUR` in `criteria.ts`). Confirm the number with your mentor.
- **Only Fase 0 exists.** The client phases after it are "…" on the Miro board. When they are
  defined, they need a column to live in, for example a choice column on `account`. Add them to
  `CustomerPhase` in `types.ts`.
- **Colours and fonts come from the 365Titans Design System** (v2.0, via the company's
  `titan-pptx-branding` skill): P600 `#7030A0` as the accent, cream background, Poppins for headings,
  IBM Plex Sans for text. The fonts are bundled, not loaded from Google. No logo is included on
  purpose: the design system allows only the approved files from Marketing, unedited.
- **Choice numbers are the platform defaults.** If your environment was customised, fix them at the
  top of `dataverseSource.ts` and nowhere else.
- **No browser back button.** It belongs to the Power Apps player, so the app never relies on it.
- Code apps need a **Power Apps Premium** licence for the people who use them.
